> [!IMPORTANT]
> An increment in the **Nekori API version** does not guarantee backward compatibility.

A Nekori API version bump is triggered by any of the following:

* **New Utility APIs or Signature Changes:** Adding convenience methods, updating parameters, or altering function return types.
* **React Native Upgrades:** Upgrading the underlying React Native runtime/engine (even if the public surface API remains identical).
* **Deprecations & Removals:** Flagging APIs scheduled for deprecation or outright removing obsolete interfaces in the upcoming release.
* **Consolidation of Upstream APIs:** Migrating/refactoring APIs implemented by LNReader into the Nekori API to eliminate duplication.
* **Runtime Behavior & Data Contract Changes:** Breaking changes in serialization, runtime polyfills, or underlying native bridge behaviors.
## Plugin authoring and Electron development

- Extend `NekoriBasePlugin` or `NekoriPagePlugin` for the Nekori contract. Legacy `PluginBase` / `PagePlugin` keep string chapter responses.
- `minApiVersion` is controlled in `plugin.ts` for the whole repository; individual plugins should not override it.
- The manifest keeps its existing array format and reads metadata from plugin instances. Nekori entries also contain `isNekoriPlugin` and `minApiVersion`.
- `outputTarget` is reserved: the current build still emits JavaScript only.
- Electron uses source modules during development. A chapter checkpoint can render its HTML in Preview, but checks report it as blocked and EPUB export stops. Video options remain in HTML markers.

## API v1 modules

| Import | Exports / behavior |
| --- | --- |
| @nekori/plugin | NekoriBasePlugin, NekoriPagePlugin; embedded by the build |
| @nekori/pluginMetadata | ContentType, ContentWarning; embedded constants |
| @nekori/aes | AES primitives from @noble/ciphers, same signatures |
| @nekori/utils | Buffer, NodeCrypto, encodeHtmlEntities, decodeHtmlEntities, getUserAgent |
| @nekori/cookie | set, get, setFromResponse, flush, removeSessionCookies |
| @nekori/webview | Not in the plugin import allowlist; implementation is reserved stubs only |

Fetch, storage, filter inputs, novel status and UTF-8 conversion remain in @libs/*.
Cookie flush persists cookies; it is not a plugin-storage flush or reader IPC.
Electron uses Node crypto and Android uses crypto-browserify; only shared algorithms are portable.

## ChapterContent

Return { state: 'ready', type: 'novel', html: '<p>Chapter</p>' } for usable content.
Types are novel, mixed, image and video. Rendering remains HTML for every type.
Use noCache to prevent response reuse, noPrefetch to stop read-ahead. These flags alone do not prohibit downloads.
For CAPTCHA, login or locked chapters return state: 'checkpoint', HTML for the reader,
noCache: true, noPrefetch: true and optionally checkpointMessage. Checks report blocked;
Android downloads and Electron EPUB export fail rather than saving the checkpoint HTML.

Plugins must not emit no-cache-marker, no-prefetch-marker or lnreader-chapter-type.
Both hosts keep these fields on ChapterContent. Legacy LNReader strings are normalized into this object; Nekori responses are never downgraded to strings. Keep other video markers
(poster, thumbnails, mode, URL, disable-progress) in HTML as before.

## Release compatibility

The manifest remains a JSON array generated by evaluating plugin metadata with mocked runtime APIs.
Nekori entries include isNekoriPlugin: true and minApiVersion: 1. Bump the API floor centrally
in plugin.ts and update the Android host together; bump each changed plugin version for delivery.
Legacy LNReader plugins retain their string contract. Nekori plugins require a host with API v1 support.
